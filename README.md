# Small Party World — 캐주얼 파티 게임 모음

여러 캐주얼 미니게임을 모아 둔 온라인 파티 게임. 대기룸에서 방장이 할 게임을 고른다.
게임은 `games/<게임id>/` 폴더 단위 모듈로 관리한다 (아래 "게임 모듈" 참고).

현재 수록 게임 (4개)
| 게임 | 폴더 | 한 줄 소개 | 인원 | 팀전 |
|---|---|---|---|---|
| **3D 돌피하기** | `games/rock_dodge` | 떨어지는 돌을 피하고 상대를 밀쳐 마지막까지 살아남기 | 2~12명 | 지원 |
| **뒷북의 달인** | `games/drum_echo` | 가면 쓴 진행자와 함께 곡에 맞춰 둥·딱 북을 치는 리듬 대결 (30곡, 난이도 1~5) | 2~12명 | 지원 |
| **무궁화 꽃이 피었습니다** | `games/mugunghwa` | 술래가 외치는 동안만 달리고 돌아보면 멈추기, 결승선을 먼저 넘으면 승리 | 2~12명 | 지원 |
| **크레이지 봄버** | `games/bomber` | 블록 탑 위에서 폭탄을 던져 블록을 깎고 상대를 맞히기, 구멍으로 떨어져도 탈락 · 탈락하면 유령이 되어 밖에서 던지기 | 2~12명 | 지원 |

게임마다 자세한 규칙은 아래 "3D 돌피하기", "뒷북의 달인", "무궁화 꽃이 피었습니다", "크레이지 봄버" 절에 있다.


## 실행
Godot 4.7.1 (서버·웹 빌더 이미지도 4.7.1 — 4.7.2는 Windows 한글 입력 버그(godot#123269)가 있어 4.7.3 출시 전까지 4.7.1 고정), Forward+ 렌더러, F5 → 접속 화면.
- **오프라인 연습**: 접속 화면의 "오프라인 연습" 버튼 (게임이 여러 개면 목록에서 선택, 봇과 대결, R 재시작, 끝나면 화면의 "다시 하기"/"메인으로" 버튼)

### 게임 동기화
서버가 방마다 경기를 직접 돌린다 (`Net` 아래 SubViewport, 방마다 독립 물리 공간):

| 항목 | 누가 정하나 | 방법 |
|---|---|---|
| 내 캐릭터 이동·점프·차징·돌진 | 내 PC | 즉시 반응. 상태를 초당 30회 서버로 전송 (서버는 속도 상한 검사) |
| 다른 캐릭터 모습 | 서버 → 모두 | 초당 20회 상태 전송, 받는 쪽은 약 0.1초 늦춰 보간 |
| 낙석·아이템·바람 생성 | 서버 | 생성 시각(서버 시계)과 궤적을 방송 → 모든 PC에서 같은 순간 같은 위치 |
| 낙석 사망·헬멧 | 서버 | 내가 보낸 "그 시각의 내 위치"로 판정 (내 화면에서 피했으면 피한 것) |
| 밀치기 | 미는 사람 PC가 맞힘을 알림 → 서버 검증 | 서버가 최근 1초 위치 기록으로 되감아 확인(최대 0.6초) 후 상대 PC에 넉백 전달 |
| 회전 기둥 | 각자 자기 캐릭터 | 각도가 경과 시간으로 정해져 모든 PC에서 같음 |
| 봇 | 서버 | 서버에서 AI·물리로 움직임 |
| 아이템 획득·사망·승패·킬 | 서버 | 결과를 방송 |

위 표는 3D 돌피하기 기준이다. **뒷북의 달인**은 움직임이 없는 리듬 게임이라 방식이 다르다: 곡 시작 시각·곡 id·노트만 서버가 알리고, 박자 판정은 각자 기기에서 반주 시계로 한 뒤 결과만 서버로 보낸다 (아래 "뒷북의 달인" 절). **무궁화 꽃이 피었습니다**는 돌피하기와 같은 방식(내 캐릭터는 내 기기, 서버가 "그 시각의 내 위치"로 판정)에 외침 주기만 서버가 정해 알린다.

- 시계: 클라이언트가 접속 중 계속 ping → 서버 시계 추정 (`Net.server_now()`)
- 메시지 통로: 게임 모듈은 `c_game`/`s_game`(확실 전달), `c_game_u`/`s_game_u`(상태용) 을 쓴다. 내용은 모듈이 정한다
- 경기 도중 방으로 나가거나 접속이 끊기면 기권(탈락)
- **경기 시작 맞추기**: 클라이언트는 경기 화면을 만든 뒤 바로가 아니라 **화면이 부드럽게 그려지기 시작한 뒤**(프레임 6개가 연달아 0.08초 안에 그려질 때, 최대 25초) 서버에 `loaded` 를 보낸다 (`PartyGame.send_loaded_when_settled`). 첫 몇 프레임의 셰이더 컴파일 렉 동안 서버가 카운트다운을 시작해 버려, 느린 기기는 멈췄다 들어가 보면 봇들이 한참 달리고 있던 문제를 막음. 서버는 모두의 `loaded` 를 최대 30초(`PartyGame.LOAD_WAIT_MAX`) 기다린 뒤 시작 시각을 알리고, 그 전에는 상태(snap)도 보내지 않음
- 웹소켓 버퍼 1MB (`Net.WS_BUFFER`, 기본 64KB) — 잠깐 멈춘 기기에 서버 메시지가 쌓여도 넘치지 않게
- 다음 라운드: 서버는 그 플레이어가 새 경기에 `loaded` 를 보낸 뒤의 상태·판정만 받는다 (결과 화면에서 보내던 예전 위치가 새 경기로 들어가지 않게)
- 서버 디버그 로그: 환경변수 `SPW_DEBUG=1` (밀치기 승인/거부 사유 출력)
- 측정(이 개발 환경, 로컬 지연 7ms): 다른 캐릭터는 약 0.1초 늦게 보이고 그 기준 위치 오차 평균 2.5cm. 서버 CPU는 경기 1개(4명)당 코어 1개의 약 11%
- 1:1로 시작한 경기는 탈락 압박(낙석 폭증)이 없음 (원래 "2명 남음" 규칙이 시작부터 걸리던 문제 수정)

### 통신
WebSocket. 서버는 컨테이너 안에서 평문 `ws://:7777`, 외부는 Caddy가 `wss://spwsv.cloudish.cloud`(443)로 받아 전달.
접속 화면의 기본 주소는 `wss://spwsv.cloudish.cloud` (`net.gd` `DEFAULT_SERVER`).

### 서버 목록 (접속 화면)
접속 화면에는 서버 **이름만** 보이고 주소는 노출하지 않습니다. 목록은 `scripts/net/net.gd` 의 `SERVER_LIST` 에서 관리:
```gdscript
const SERVER_LIST := [
    {"name": "서버 1", "url": DEFAULT_SERVER},
    # {"name": "서버 2", "url": "wss://다른서버주소"},
]
```
에디터 실행·디버그 빌드에서만 "로컬 테스트 (이 PC)" 항목과 "이 PC에서 서버 열고 접속" 버튼이 보이고, 릴리스·웹 빌드에서는 숨겨집니다.

### 도메인
| 도메인 | 용도 |
|---|---|
| `spwsv.cloudish.cloud` | 게임 서버(중계 서버). 게임 접속(wss) + 브라우저로 열면 서버 상태 페이지 |
| `spw.cloudish.cloud` | 안내 페이지 — PC(Windows)는 PC 버전 다운로드, 모바일은 앱 설치로 유도 (`deploy/web-landing`) |
| (안내 페이지 공통) | 소개(`/about/`)는 좌우로 넘기는 슬라이드 (`deploy/web-landing/pager.js` → `/assets/pager.js`): `data-slides`(수록 게임·조작법, 게임 안 사진은 `data-slides="dots"`), 좁은 화면에선 카드 줄(`hscroll`)을 옆으로 밀기. `#아이디` 링크는 그 슬라이드를 열어 줌. 약관·방침·문의는 세로로 길게 그대로 (`<main data-pages="all">` 를 붙이면 h2 마다 한 쪽으로 나눌 수 있음). 자바스크립트가 없으면 모두 펼쳐짐 |
| `spw.cloudish.cloud/play/` | 웹 체험판 (Godot 웹 빌드). 게임 첫 화면 오른쪽 위에도 PC 버전/앱 안내 카드 |
주소 칸 입력 규칙: 도메인 → `wss://도메인`, IP/localhost → `ws://IP:포트`(기본 7777), `ws://`·`wss://`는 그대로.

### 홈서버 배포 (Ubuntu + Docker Compose + Caddy)
1. 이 프로젝트 폴더를 홈서버로 복사 (git 또는 scp)
2. 프로젝트 폴더에서 빌드·실행
   ```bash
   docker compose up -d --build
   docker compose logs -f              # "[server] 대기 중 — 포트 7777" 확인
   curl http://127.0.0.1:7778/health   # "ok" 가 나오면 서버 정상
   docker ps                           # STATUS 에 (healthy) 표시
   ```
3. Caddy 설정 추가 — `deploy/Caddyfile.example` 참고
   - Caddy를 Ubuntu에 직접 설치: `reverse_proxy 127.0.0.1:7777` (compose 기본값 그대로)
   - Caddy도 Docker: compose의 `ports` 대신 Caddy와 같은 네트워크에 연결하고 `reverse_proxy small-party-world-server:7777`
   - 반영: `sudo systemctl reload caddy` 또는 `docker exec <caddy> caddy reload --config /etc/caddy/Caddyfile`
4. 브라우저로 `https://spwsv.cloudish.cloud` 열기 → **서버 상태 페이지**(접속자·방 목록)가 보이면 Caddy 연결 정상
5. 게임 클라이언트에서 기본 주소(`wss://spwsv.cloudish.cloud`)로 접속
   웹 게임 페이지(`spw.cloudish.cloud`)는 웹 빌드 전까지 `deploy/web-placeholder/index.html`을 `/srv/small_party_world/web/`에 넣어 두기
6. 업데이트: 코드 변경 후 `docker compose up -d --build`

### 여러 라운드 경기 (시리즈)
- 방장이 대기룸에서 **라운드 수(1~5)** 와 **라운드별 게임**(같은 게임 여러 번 가능, "랜덤" 가능)을 정한다
- 게임을 시작하면 1라운드 → 끝나면 결과 화면에서 **다음 라운드 레디** (모두 레디하거나 30초 지나면 다음 라운드 자동 시작)
- 라운드 승점: **1등 3점 · 2등 2점 · 3등 1점** (모든 게임 동일, 동점은 같은 점수). 팀 게임은 팀 순위로 팀원 모두가 같은 점수
- 마지막 라운드가 끝나면 합계 1위가 최종 우승(같으면 공동 우승) → "방으로 돌아가기"
- 결과 화면에서 "방으로 나가기"를 누르면 남은 라운드에서 빠진다
- 서버 규칙: `scripts/core/series.gd`, 결과 화면: `scripts/ui/series_panel.gd`
- 새 게임은 경기가 끝날 때 서버에서 `report_result(placements)` 를 부르기만 하면 된다 (`scripts/core/party_game.gd`)

### 캐릭터 목소리
- `tools/audio/gen_voice.py` 로 코드만으로 합성한 아이 목소리 감탄사 (녹음·샘플 없음). 파일 `audio/sfx/voice_<종류>_<목소리>_<번호>.wav` (22kHz, 모두 216개 약 3.6MB)
- 목소리 9가지(0 보통 아이 / 1 여자아이 / 2 굵은 목소리 / 3 아주 얇고 높은 목소리 / 4 우락부락한 털보 아저씨 / 5 대머리 장사 / 6 핑크 대머리 / 7 할머니 / 8 로봇) — 캐릭터 외형 12가지마다 목소리 종류와 음높이가 정해져 12명이 모두 다르게 들림(`Fighter.LOOK_VOICE`): 짧은 머리 보통 아이 / 양갈래 여자아이 / 삐죽 머리 굵은 목소리 / 단발 아주 얇고 높은 목소리 / 올림머리 조금 낮은 여자아이 / 모자 조금 높은 아이 / 털모자 털보 아저씨(턱수염·콧수염·굵은 눈썹이 붙음) / 머리띠 조금 높은 굵은 목소리 / 대머리 장사(콧수염, 털보보다 더 두껍고 낮은 목소리) / 핑크 대머리(핑크 옷·하트 안경, 얇고 하늘하늘한 목소리) / 뽀글머리 할머니(동그란 안경, 덜덜 떨리는 목소리) / 로봇 헬멧(한 음으로 말하는 전자음)
- 종류: charge 차징을 시작할 때 "흐으으읍~"(2, 예전 차징 효과음 대신 — 돌피하기·무궁화·크레이지 봄버 모두) / push 밀칠 때·차징 던지기 기합(4) / hit 맞았을 때(4) / die 탈락(3) / jump 점프(3, 45% 확률) / pickup 아이템 먹음(3) / win 경기 끝에 살아남은 캐릭터 환호(3) / laugh 상대를 떨어뜨리거나 폭탄으로 맞혔을 때(2) / surprise 크레이지 봄버에서 폭탄이 내 폭발 범위 안에 떨어질 때 "헉!"(2)
- 대사 (TTS): `tools/audio/gen_tts_lines.py` — 한국어 TTS 모델(sherpa-onnx 1.13.8 + vits-mimic3 ko_KO-kss, 깃허브에서 받음)로 만든 짧은 말. 파일 `audio/sfx/line_<종류>_<목소리>_<번호>.wav` (207개 약 3.5MB). 빠르게(낭독의 1.45배) 말하게 하고, 목소리 5가지는 높이 배율로(털보는 걸걸하게 포화·떨림까지)
  - win "야호!·이겼다!·우하하하!·내가 일등이다!" / die "아이씨!·짜증나!·으아악!·안 돼애!" / hit "아야야!·아이씨!·아이고!" / pickup "아싸라비아!·좋았어!·득템!" / laugh "우하하!·메롱!·히히히!" / push "받아라!·에이잇!·간다!" / surprise "허억!·어머나!·앗 뜨거!"
  - 목소리를 낼 때 종류마다 정한 확률(`Fighter.LINE_CHANCE`, 30~60%)로 합성 감탄사 대신 대사를 고른다
- 온라인에서는 다른 사람 캐릭터의 상태 표시(밀치기·경직·바닥에서 뜸)가 바뀔 때 내 PC 에서도 목소리를 낸다(`FighterSync.apply_flags`). 같은 종류는 0.4초 안에 두 번 안 냄(`Fighter._voice`). 음량은 종류별(`Sfx.MIX` 의 `voice_<종류>`)

### 불러오는 중 표시
- 게임 시작을 누르거나(방장), 서버가 경기 시작을 알리거나, 다음 라운드·혼자 연습으로 넘어갈 때 `scripts/ui/loading_overlay.gd` 가 화면을 살짝 어둡게 하고 가운데에 도는 표시와 "게임 불러오는 중…" 을 띄운다. 씬을 바꾸기 전에 두 프레임 기다려 표시가 먼저 그려지게 함
- 경기 화면에서는 `scripts/ui/loading_watch.gd`(PartyGame.add_common_ui 가 붙임)가 이어받아, 화면 준비가 끝나면(loaded 보냄) "다른 플레이어를 기다리는 중…", 서버의 시작 신호가 오면 닫는다. 메뉴에서 10초 넘게 그대로면(시작 거절 등) 스스로 닫힘

### 팀전
- 방장이 대기룸에서 **개인전(1:1:1…) / 2팀전 / 3팀전 / 4팀전** 을 고른다. 팀을 정하면 사람들이 팀에 고르게 나뉘고, 각자 카드의 "→ 팀" 버튼으로 바꾼다 (방장은 다른 사람도 옮길 수 있음)
- 팀끼리 인원이 맞아야 시작: 봇 채우기를 끄면 팀별 사람 수가 같아야 하고, 켜면 최대 인원이 팀 수로 나누어떨어져야 하며 빈자리는 봇이 채운다
- 출발 자리: 팀전이면 팀이 번갈아 선다 (같은 팀끼리 뭉치지 않게, `PartyGame.mixed_spots` — 돌피하기 원형·무궁화 출발선·크레이지 봄버 출발 칸. 뒷북의 달인은 팀별 무대라 그대로)
- 팀 수를 바꾸면 최대 인원이 팀 수의 배수로 자동 조정 (`Teams.fit_max`, 올림 우선·게임 최대 넘으면 내림. 예: 5명 → 2팀 6명, 4팀 8명). 대기룸 인원 칸도 팀 수 단위로만 바뀜
- 경기 도중 누가 나가면 그 캐릭터를 봇이 이어받고, 다음 라운드에도 그 자리는 봇이 채운다
- 팀 순위: 돌피하기는 팀원이 마지막까지 남아 있던 시각 순, 뒷북의 달인은 팀원 점수 합계 순, 무궁화는 팀원 도착 점수 합(먼저 들어온 순서대로 인원수점, 인원수-1점 … — 12명이면 1등 12점) → 가장 먼저 들어온 팀원 → 가장 멀리 간 팀원 순, 크레이지 봄버는 살아남은 팀원 수 → 마지막 팀원이 탈락한 시각 순. 팀원 모두가 팀 순위 점수(3/2/1)를 받는다
- 돌피하기: 같은 팀끼리도 밀칠 수 있다 (팀킬). 팀킬은 킬 수에 들어가지 않는다. 봇은 같은 팀을 노리지 않는다
- 규칙: `scripts/core/teams.gd`. 새 게임이 팀전을 지원하면 module.gd 에 `supports_teams = true`

### 버전 관리·업데이트
버전은 저장소 맨 위의 `release.json` 한 곳에서 관리한다.

```json
{ "version": "0.2.0", "min_supported": "0.2.0", "pc_full_required": false, "notes": ["바뀐 점", "..."] }
```

- **새 버전 내기**: `version` 을 올리고 `notes` 를 쓴 뒤 `main` 에 푸시 → CI 가 `https://spw.cloudish.cloud/version.json` 을 갱신
  - 게임은 켤 때 이 파일을 읽어 첫 화면에 "새 버전" 카드와 업데이트 버튼을 띄운다
  - 같은 `version` 으로 다시 푸시하면 이미 받은 사람에게는 다시 내려가지 않는다 → 배포할 때마다 버전을 올릴 것
- **PC 앱**: 업데이트 버튼 → 업데이트 팩(`/download/updates/game-<버전>.pck`)을 받아 sha256·서명 확인 → 다시 시작하면 적용
  (`scripts/core/boot.gd` 가 다른 스크립트보다 먼저 팩을 불러옴)
  - Godot 버전을 바꿨거나 `project.godot`(자동 로드·설정)·내보내기 설정을 바꿨으면 `"pc_full_required": true` → 전체 zip 을 받도록 안내
  - **자동 보호** (팩으로는 `project.godot` 설정이 안 바뀌기 때문. 예: 0.6.0 에서 Account·Ads 자동 로드가 생겨 그 전 설치본에 새 팩을 적용하면 Net 이 깨져 강제 종료됐음)
    - 설정 지문 `Boot.settings_sig()` = 자동 로드(이름·경로) + 입력 동작 이름. `version.json` 의 `pc.settings_sig` 가 설치본과 다르면 팩 대신 전체 zip 안내, 이미 받은 팩도 쓰지 않음
    - 팩을 적용해 시작하면 자동 로드가 모두 떴는지 확인 → 하나라도 없으면 팩을 버리고 설치본으로 다시 시작
    - 팩을 적용해 시작했다는 표시(`user://updates/boot_try.txt`)를 남기고 8초 버티면 지움 → 남아 있으면(강제 종료) 다음 실행 때 팩을 버림
    - 이 보호는 설치본(전체 zip)의 Boot 에 들어 있어야 하므로 0.7.4 는 `pc_full_required: true`
  - 서명 키: GitHub Secrets `PATCH_SIGNING_KEY` (RSA 개인 키 PEM). 공개 키는 `scripts/core/updater.gd` 의 `PUBLIC_KEY`. 키가 없으면 팩을 올리지 않고 전체 zip 안내
- **Android·iOS**: 스토어 정책상 앱이 스스로 코드를 바꾸면 안 되므로 버튼은 스토어(출시 전에는 APK) 페이지를 연다
- **웹**: 새로고침
- **최소 버전** `min_supported`: 이보다 낮은 게임은 서버가 로그인을 거절하고, 첫 화면도 업데이트를 안내한다 (혼자 연습은 가능).
  모바일 스토어 심사가 끝나기 전에는 올리지 말 것
- 서버·클라이언트 통신 형식이 바뀌면 `scripts/net/net.gd` 의 `PROTOCOL_VERSION` 도 올린다

### 자동 빌드·배포 (GitHub Actions)
`main` 에 푸시하면 `.github/workflows/build-deploy.yml` 이 돈다. (GitHub > Actions 에서 수동 실행도 가능)

| 작업 | 어디서 | 하는 일 |
|---|---|---|
| deploy | 홈서버 (셀프 호스티드 러너, 라벨 `homeserver`) | 게임 서버 재빌드·재시작 → 웹(안내 페이지·체험판·Windows zip) 빌드·배포 → 상태 확인 |
| android | GitHub 리눅스 러너 (공개 저장소라 무료) | AAB 빌드 → Google Play **내부 테스트** 트랙 업로드 + 같은 키로 서명한 APK 빌드 |
| android-apk | 홈서버 | 그 APK 를 `https://spw.cloudish.cloud/download/SmallPartyWorld-android.apk` 에 게시 (폰에서 받아 바로 설치해 보는 용도, 안내 페이지에는 링크 없음) |
| iOS | (예정) 이 Mac 을 셀프 호스티드 러너로 | Apple 개발자 계정 재결제 후 TestFlight 업로드까지 |

**1) 홈서버 러너 설치 (한 번)**
1. GitHub 저장소 > Settings > Actions > Runners > New self-hosted runner > Linux — 나오는 명령을 홈서버에서 실행
2. `./config.sh` 에서 라벨을 물으면 `homeserver` 추가
3. 서비스로 등록: `sudo ./svc.sh install && sudo ./svc.sh start`
4. 러너 사용자가 docker 를 쓸 수 있게: `sudo usermod -aG docker <러너 사용자>` (그 후 서비스 재시작)
5. 저장소 > Settings > Actions > General > "Fork pull request workflows from outside collaborators" 를
   **Require approval for all outside collaborators** 로 (공개 저장소 보안). 워크플로는 main 푸시에만 반응한다
6. 기존 수동 명령(`~/spw` 에서 `docker compose …`)과 같은 프로젝트 이름(`spw`)을 쓰므로 섞어 써도 된다

**2) Android 업로드 준비 (한 번)**
1. 업로드 키 만들기 (분실하면 앱 업데이트 불가 — 안전하게 보관):
   `keytool -genkeypair -v -keystore spw-release.keystore -alias spw -keyalg RSA -keysize 2048 -validity 10000`
2. 저장소 > Settings > Secrets and variables > Actions 에 시크릿 추가
   - `ANDROID_KEYSTORE_BASE64` = `base64 -i spw-release.keystore` 결과
   - `ANDROID_KEY_ALIAS` = `spw`, `ANDROID_KEY_PASSWORD` = 키 비밀번호
3. 첫 AAB 는 Play Console 에서 직접 올린다 (Actions 실행 결과의 `android-aab` 아티팩트 다운로드 → 앱 만들기 → 내부 테스트에 업로드).
   패키지 이름 `cloud.cloudish.spw` — **첫 업로드 후에는 바꿀 수 없음** (`export_presets.cfg` Android 프리셋)
4. 자동 업로드: Google Cloud 서비스 계정 만들기 → Play Console > 사용자 및 권한에서 그 계정에 앱 권한 부여 →
   JSON 키를 시크릿 `PLAY_SERVICE_ACCOUNT_JSON` 에 넣기
5. 앱이 처음 검토를 통과하기 전에는 Play 가 "초안(draft)" 업로드만 허용한다. 통과 후 저장소 변수(Variables)
   `PLAY_RELEASE_STATUS` = `completed` 로 바꾸면 내부 테스트에 바로 배포된다
- 시크릿이 없으면 Android 작업은 경고만 남기고 건너뛴다
- 버전 코드는 Actions 실행 번호로 자동 증가, 버전 이름은 Android 프리셋의 `version/name`
- 개인 개발자 계정(2023-11-13 이후 생성)은 정식 출시 전에 12명 이상 · 14일 연속 비공개 테스트가 필요하다

**3) Google Play 스토어 출시 순서**
1. Play Console > 앱 만들기 — 앱 이름, 기본 언어(한국어), 게임, 무료
2. 대시보드 "앱 설정" 항목 채우기
   - 개인정보처리방침 URL (모든 앱 필수, 앱 안에도 링크 필요)
   - 앱 액세스(로그인 없음), 광고 여부, 콘텐츠 등급 설문, 타겟 연령층, 데이터 보안 양식(닉네임·접속 정보 처리 방식)
   - 스토어 등록정보: 짧은 설명, 자세한 설명, 아이콘 512×512, 그래픽 이미지 1024×500, 휴대전화 스크린샷 2장 이상
3. 테스트 > 내부 테스트 > 새 버전 > Actions 의 `android-aab` 를 업로드 (첫 업로드는 수동).
   이때 Play 앱 서명을 사용 — Google 이 배포 서명 키를 관리하고, 우리 키는 "업로드 키"가 된다
4. (개인 계정) 비공개 테스트 트랙에 12명 이상 테스터를 14일 연속 참여시킨 뒤 > 프로덕션 액세스 신청
5. 프로덕션 > 새 버전 만들기 > 검토 제출 → 승인되면 공개. 이후 업데이트는 Actions 가 올린 빌드를
   내부 테스트에서 확인한 뒤 Play Console 에서 "버전 승격"으로 비공개/프로덕션에 올린다
6. 출시 후 `deploy/web-landing/links.json` 의 `android` 에 스토어 주소(`https://play.google.com/store/apps/details?id=cloud.cloudish.spw`)를 넣고 푸시

**주의: 서버와 앱 버전.** 서버·웹은 푸시 즉시 바뀌지만 스토어 앱은 심사·업데이트가 늦다.
`net.gd` `PROTOCOL_VERSION` 을 올리는 변경은 이미 설치된 앱의 접속을 막으므로, 앱 출시 후에는 호환 유지 또는 강제 업데이트 안내가 필요하다.

### 서버가 예전 버전일 때 (접속 후 무한 로딩·상태 페이지가 casual_games)
상태 페이지(`https://spwsv.cloudish.cloud`)의 이름·Godot 버전·프로토콜 버전으로 서버 버전을 확인할 수 있다.
정상: `Small Party World` · `Godot 4.7.1` · `프로토콜 v4` (`net.gd` `PROTOCOL_VERSION`)
```bash
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'   # 7777/7778 을 쥔 컨테이너 확인
docker rm -f <예전 컨테이너 이름>        # 예전 casual_games 서버가 남아 있으면 제거
cd <홈서버의 spw 폴더>                   # 최신 코드로 갱신(git pull 또는 복사) 후
docker compose up -d --build
curl -s http://127.0.0.1:7778/status.json   # "game":"Small Party World", "godot":"4.7.1…", "protocol":4
docker compose --profile build run --rm web-build   # 웹 게임도 같은 버전으로
```
클라이언트와 서버의 프로토콜 버전이 다르면 로그인 단계에서 안내 문구가 뜨고, 서버가 아예 예전 형식이면 6초 뒤 "응답 없음"으로 끝난다.

# 3D 돌피하기 (`games/rock_dodge`)

## 조작
| 입력 | 동작 |
|---|---|
| WASD | 이동 — 캐릭터는 이동 방향을 바라봄 (밀치기도 바라보는 방향으로). 돌진·밀치기 직후 정지 중과 경직 중엔 방향이 안 바뀜 |
| 마우스 | 카메라만 회전 (방향키는 카메라 기준) |
| Space | 점프 |
| 좌클릭 / E 짧게 | 제자리 밀치기 (쿨타임 0.3초) |
| 좌클릭 / E 길게 | 차징 — 이동 감속 + 바닥 화살표(길이 = 돌진 거리). 떼면 바라보는 방향으로 돌진하며 밀쳐냄. 차징 중엔 발밑에 주황→빨강 고리(모두에게 보임). 돌진 화살표는 나에게만 보임 **점프해도 유지, 공중에서도 밀치기·차징 가능** (공중에서 맞아도 땅에서 맞은 것과 같은 넉백) |
| R | 재시작 |
| Esc | 마우스 해제 (클릭으로 복귀) |
| V / 오른쪽 위 시점 버튼 | **시점 바꾸기 (모든 게임 공통)**: 기본 시점(처음 거리) → 넓은 시점(기본과 최대의 중간) → 전체 시점(휠로 끝까지 민 거리) → 기본. `Fighter.cycle_view`, 거리는 `cam_default_len`·`cam_max_len`. 뒷북의 달인은 자동 연출 → 무대 정면 → 전체 시점(`drum_game.view_mode`) |

## 규칙
- **낙석**: 바닥의 원이 착지 지점과 위험 범위. 노랑 → 빨강으로 차오르고 직전에 깜빡임. 닿으면 즉사
- **시작 보호**: 경기 시작 후 5초 동안은 캐릭터 주변(3m + 돌 반지름)에 낙석이 떨어지지 않음
- **낙석 위치**: 아레나 전체에 균등 랜덤 (`rock_dodge_game.gd` `target_player_ratio`로 캐릭터 조준 비율 조절 가능)
- **바람**: 5~9초마다 풍향·풍속이 바뀜. 돌은 생성 순간의 바람을 받아 사선 직선으로 떨어짐
  (우상단 나침반 = 카메라 기준 풍향, 풀과 바람 입자도 같은 방향으로 움직임)
- **밀치기**: 맞은 쪽은 넉백 + 경직(조작 불가). 밀려나는 거리는 탭·차징 모두 풀차징과 같고, 차징할수록 돌진 거리·경직·쿨타임 증가
  - 탭: 제자리 밀기(0.3초간 정지, 사거리 2.5m), 넉백 9, 경직 0.25초, 쿨 0.3초
  - 차징: 돌진 1.9~6.8m, 넉백 12~20, 경직 0.8~1.5초, 쿨 0.6~1.8초. 돌진 후 제자리 정지: 맞히면 0.25~0.45초, **헛치면 0.4~0.7초**
  - 경직 상한 1.5초 (글러브·벽꽝 포함). 경직이 풀린 뒤 0.5초는 다시 경직되지 않음 (넉백만 받음)
  - 풀차징(1.2초, 차징 가속 아이템으로 단축): 가장 멀리 돌진. 무적은 없음 (무적은 무적 아이템으로만)
- **회전 기둥**: 중앙 축을 중심으로 바닥에 누운 기둥(양쪽 팔)이 시계침처럼 회전. 점프로 넘어야 함.
  - 벽처럼 단단해서 어느 방향에서도 걸어서 통과 불가
  - 회전 진행 방향 쪽에서 닿으면 강하게 밀림(넉백 17·경직 1.5초). 뒤쪽에서 닿으면 그냥 막힘
  - 밀려 날아가다 기둥에 부딪히면 아레나 벽과 똑같이 벽꽝(경직 1.5배)
  - 회전 속도는 난이도에 따라 0.35→0.6 rad/s
- **몸 충돌**: 캐릭터끼리 부딪히면 살짝 튕김
- **벽꽝**: 밀려서 벽(아레나 벽·회전 기둥)에 부딪히면 경직 1.5배
- **당구 연쇄**: 밀려 날아가던 캐릭터가 다른 캐릭터와 부딪히면 그 캐릭터도 날아감
- **맞밀치기**: 마주 보고 동시에 밀면 둘 다 크게 튕김 (무적 상태면 일방적으로 이김)
- **킬 크레딧**: 내가 민 상대(연쇄 포함)가 3초 안에 낙석에 맞으면 내 킬
- **관전**: 탈락하면 1초 뒤 나를 떨어뜨린 사람(없으면 다른 생존자) 시점으로 바뀜. 화면 아래 ◀ ▶ 버튼(키보드 ← →)으로 다른 생존자 시점 선택. 경기가 끝나면 결과 화면 버튼(방으로 돌아가기 / 다시 하기 · 메인으로)

## 아이템 (2~3.5초마다 아레나에 등장, 최대 5개, 15초 후 소멸)
인원이 줄수록 등장 간격이 늘어남(2명 남으면 2배). 2명 남으면 무적 아이템은 나오지 않음.

| 아이템 | 효과 |
|---|---|
| 헬멧 | 낙석 1회 방어, 최대 2개 중첩 (안전모: 노랑 1개 / 빨강+흰 띠+2단 돔 2개) |
| 차징 가속 | 풀차징까지 걸리는 시간 단축 (1개당 차징 속도 +25%). 경기 끝까지 유지, 최대 3개 중첩 |
| 쿨타임 감소 | 밀치기 쿨타임 단축 (쿨타임 = 기본 ÷ (1 + 0.2×개수)). 경기 끝까지 유지, 최대 3개 중첩 |

# 뒷북의 달인 (`games/drum_echo`)
가면 쓴 진행자가 곡에 맞춰 북을 치고, 모든 플레이어가 진행자가 치는 바로 그 자리에서 함께 치는 리듬 대결 (태고의 달인처럼 노트가 다가옴).

## 조작
| 입력 | 동작 |
|---|---|
| Space (F 도 됨, 화면 왼쪽 큰 버튼) | 둥 (왼쪽 큰 주황 북). 피버는 누르고 있다가 떼기 |
| Enter (J 도 됨, 화면 오른쪽 큰 버튼) | 딱 (오른쪽 작은 보라 북) |

  - 곡 구성은 대개: 전주 → 1절 → 후렴 → 간주 → 2절 → 후렴 2(끝에 피버) → 마무리. 난이도는 노트 밀도·엇박(16분 당김) 정도로 나눔. 빠른 곡(160 BPM 넘음)은 16분음표가 0.09초보다 짧아져서 8분까지만 씀
  - BPM 은 곡마다 다름: 차례마다 `beat`·`bar`(초)를 실어 두고 트랙 박 선·피버 '드르륵' 간격(16분음표)이 그것을 씀. 판정 창(±45/90/140ms)은 BPM 과 상관없이 같음
- **피버** = 누르고 있다가 끝 박자에 떼는 노트 (누름·뗌 각각 판정, 노트 2개)
- **판정**: 같은 북·같은 타이밍 ±45ms PERFECT 100 · ±90ms GOOD 60 · ±140ms BAD 20 · 못 치면 MISS 0 · 노트 없는 곳을 치면 '헛침' −10
- **승패**: 곡이 끝나면 팀원 점수 합계(개인전은 개인 점수)로 순위 → 라운드 승점. 봇은 실력(`BOT_SKILL`)대로 판정
- **판정은 각 플레이어 기기에서** 한다: 누른 순간 그 기기가 반주 박자를 기준으로 판정하고, 서버에는 결과만 보낸다 (`["res"|"resrel", ...]` → `_apply_result`). 서버는 박자를 다시 재지 않고 앞뒤(노트 번호·이미 맞힌 노트 아닌지·판정 값)만 확인해 점수에 반영하고 모두에게 알림
- **누름 = 움직임**: 누름·뗌은 판정과 별개로 `["key", lane, 1|0]` → 서버가 `["k", slot, lane, 1|0]` 로 모두에게 → 그 캐릭터가 바로 북을 침, 누르고 있는 동안(피버)은 팔을 내린 채로 (`Fighter.drum_hold_l/r`)
- 시계: 트랙·판정 모두 '귀에 들리는 반주 시각'(`heard_time` = 반주 시계 − 소리 출력 지연(`AudioServer.get_output_latency`))
  - **반주가 기준 시계**: 반주가 몇 바퀴째인지 직접 세서 곡 시간을 낸다 (사운드카드 시계와 컴퓨터 시계 차이로 곡 후반 트랙이 순간이동하던 문제 해결). 1초 넘게 어긋날 때(멈춤 등)만 다시 맞춤
  - 화면 시계는 실제로 흐른 시간만큼 매끄럽게 가고, 반주 위치의 작은 들쭉날쭉(오디오 버퍼 단위)은 천천히 흡수. 키 입력 시각도 마지막 갱신 뒤 흐른 시간을 더해서 잼
- 트랙(하나): 노트(꽉 찬 원)가 오른쪽에서 다가와 왼쪽 판정 동그라미에 닿을 때 친다 (진행자도 같은 순간에 침). 앞뒤 차례가 이어져 보이고, 북 마디 구간만 밝고 쉬는 구간은 어둡게. 마디 첫 박 선은 굵게. 안내 글은 트랙 바로 위
- 화면: 팀은 바닥 색으로 구분 (팀원이 선 자리를 팀 색 큰 원판으로 이어 칠함). 북은 주황(둥)·보라(딱)
- 카메라: 음악방송처럼 샷을 골라 컷을 바꾸고 샷 안에서 천천히 돌거나 다가감 (`SHOTS`, `_pick_shot`). 연주 중엔 연주자를 한 명씩 번갈아 클로즈업(약 2초마다) + 무리·위에서 + 가끔 진행자
- 소리: 반주에는 북이 없음. 내 북(크게)과 다른 캐릭터의 북(작게)이 곡마다의 북 소리로 남. 판정 소리(MISS·헛침) 없음, 북 버튼은 딸깍 소리 없음(`no_click` 메타, `Sfx._on_button_pressed`). 다른 연주자(사람·봇)는 소리 없이 머리 위 판정 글자(PERFECT/GOOD/BAD/MISS)로만 표시 — 한 사람 위에는 하나만 (`_judge_pop`, 새 판정이 앞 판정을 바꿈) (봇 판정은 서버와 같은 시드의 `Chart.bot_judgements`)
- 성능: 이 게임은 무대만 보므로 그림자 범위 28m·2단, 무대에서 30m 밖 풀 숨김, 작은 부품 그림자 끔, 북 재질 공유, PC는 VSync mailbox (입력 지연 감소, 나가면 원래대로)

# 무궁화 꽃이 피었습니다 (`games/mugunghwa`)
긴 운동장 끝의 커다란 술래(가면 쓴 진행자)가 뒤돌아 "무궁화 꽃이 피었습니다"를 외치는 동안만 달리고, 돌아보면 멈추는 게임.

## 조작
돌피하기와 같다 (WASD·스틱 이동, Space 점프, 좌클릭/E 밀치기). 빨간불엔 손을 떼야 한다.

## 규칙 (`games/mugunghwa/mugunghwa_game.gd`)
- 운동장: 폭 = 인원 × 2m (`WIDTH_PER_PLAYER`, 최소 8m·최대 24m — 모든 PC에서 같은 인원으로 계산). 출발선에 한 줄로 2m 간격(팀전은 팀이 번갈아), 출발선 z=+27 → 결승선 z=−23 (50m), 술래는 z=−28 단상 위 (4.2배 크기). 투명 벽으로 둘러쌈. 경기장이 넓어서 `module.gd` 의 `arena_half = 32` (월드가 지형의 평평한 구역·풀·나무 배치를 이 값으로 함 — `GameModule.arena_half`)
- 외침 주기: 초록불(술래가 뒤돌아 외침, `GREEN_MIN`~`GREEN_MAX` 1.3~3.6초, 갈수록 짧은 외침이 잦음) → '다' 소리가 나는 순간 홱 돌아봄(`TURN_TIME` 0.15초) → 빨간불(1.6~3.2초, 18% 확률로 4~5.5초 — 다시 외치기까지 한참 뜸)
  - 외침 스타일 9가지 (`STYLES` — [첫 소리 전 침묵, 음절 10개 길이 비율] + 최소 길이): 고르게 / 끝을 몰아치기 / '화'에서 뜸 / 끝을 늘이기 / '니'에서 뜸 / 한참 침묵 뒤 빠르게 / 두 번 뜸 / 무~ 길게 / 침묵·느리게·빠르게·뜸. 첫 외침은 늘 '고르게'. 침묵 동안은 초록불(화면 외침 칸에 '…'). 음절마다 한 음 (`audio/mugunghwa/chant.wav` 를 `CHANT_PITCH` 높이로)
  - 술래 옆 신호등(큰 공)과 화면 신호등: 초록 = 달려요, 노랑 = 돌아보는 중, 빨강 = 멈춰요
- **탈락**: 빨간불이 되고 `GRACE`(0.1초) 뒤의 위치를 기준으로 (= '다'가 들리고 0.25초 뒤. 키를 떼도 조금 미끄러지므로 실제로는 '다' 뒤 약 0.15초 안에 떼야 안전), 0.2m 넘게 움직이거나 점프하면 탈락. 밀려서 움직여도 탈락, 빨간불에 밀치기·차징을 해도 탈락
  - 그래서 초록불 끝에 옆 사람을 밀어 빨간불까지 미끄러지게 하는 수싸움이 생김 (봇 중 공격적인 봇도 가끔 함)
- **통과**: 결승선을 넘으면 통과 (순서대로 1등, 2등 …). 통과한 사람은 결승선 뒤에 머문다 (다시 들어와 방해 못 함, 밀치기도 안 됨)
- 제한 시간 50초 (`TIME_LIMIT`): 끝날 때 못 넘은 사람은 '시간 초과' 탈락
- 순위: 통과 순서 → 못 넘은 사람은 결승선에 가까이 간 순(탈락한 자리 기준). **팀전은 도착 점수**: 먼저 들어온 사람부터 인원수점, 다음은 1점씩 적게(12명이면 1등 12점, 2등 11점 …, 못 들어오면 0점, `arrival_points`). 팀원 점수를 더해 높은 팀부터 순위(같으면 가장 먼저 들어온 팀원 → 가장 멀리 간 팀원) → 라운드 승점 1등 팀 3점·2등 팀 2점·3등 팀 1점. 화면 위에 팀별 점수가 보이고, 통과 알림에 "+N점"
- 온라인: 서버가 외침 주기를 서버 시계 기준 시각으로 알림 (`["cycle", idx, 초록불 시작, 외침 길이, 빨간불 길이, 스타일]`). 판정은 클라이언트가 보낸 "그 시각의 내 위치"로 하므로 내 화면에서 제때 멈췄으면 멈춘 것. 밀치기·상태 전송·보간은 돌피하기와 같은 코드
- 봇 (`bot_brain.gd`): 사람보다 느리게 달림(세기 0.5~0.75), 외침이 시작되면 0.15~0.6초 뒤 출발, '다'를 듣고 멈춤. 겁 많은 봇은 미리 멈추고, 봇마다 4~14% 확률로 늦게 멈춰서 걸림. 보통 제한 시간 가까이 가서야 들어옴. 공격적인 봇은 외침 끝 무렵 바로 옆 상대를 툭 민다
- 화면 (`hud.gd`, 돌피하기 HUD 를 이어받음): 위 = 남은 시간·통과·탈락·남은 인원, 가운데 = 외친 음절만 보이는 외침 글자 · "멈춰!", 오른쪽 = 진행 막대(모두의 위치, 나는 크게), 빨간불이면 화면 가장자리가 붉게. 탈락하면 아직 달리는 사람 관전
- 개발용: `no_out = true` 면 탈락 판정 끔 (사진 찍기용)
- **다음 라운드 버그 수정 (0.13.1)**: 같은 게임을 연달아 하면, 클라이언트가 결과 화면에서 계속 보내던 위치(결승선 너머)가 서버의 새 경기로 들어가 시작하자마자 통과 처리됐다. 이제 서버는 그 플레이어가 새 경기에 `loaded` 를 보낸 뒤 + 경기 시작 시각 뒤의 상태만 받는다. 돌피하기(위치)·뒷북의 달인(판정 결과·누름)에도 같은 막음을 넣었다

# 크레이지 봄버 (`games/bomber`)
격자의 칸마다 2m 정육면체 블록이 4층 쌓인 평평한 탑 위에서 폭탄을 **포물선으로 던져** 블록을 깎고 상대를 맞히는 게임. 터질수록 지형이 낮아지고 구멍이 뚫려 아래 용암이 드러난다. 전체적으로 빠르게(이동·폭탄·폭발) 진행된다.

## 조작
- 이동: WASD·스틱 (카메라 기준). Space(모바일 '점프' 버튼) = 점프 — 약 4.3m, 블록 2층까지 한 번에 오름. 이동 속도 7.2m/s, 캐릭터는 1.3배 크기(`Fighter.body_scale`)
- **폭탄: 좌클릭/E (모바일 '던지기' 버튼)** — 짧게 탭하면 발밑에 놓기, 누르고 있다가 떼면(차징) 차징한 만큼 세게 바라보는 방향으로 던지기 — **물리로 계산**: 가슴 높이(1.3m)에서 바라보는 방향으로 똑바로, 발사 속도(수평 4.5~20.5m/s, 위 1.5~3m/s — 꼭대기가 던진 높이보다 0.06~0.23m 위인 아주 낮은 포물선) + 내 몸 속도 중 앞으로 가는 성분의 60%(옆으로는 휘지 않음) + 점프해 올라가는 속도의 60% + 폭탄 중력 20m/s². 궤적이 처음 닿는 블록 칸을 찾아(`simulate_throw`) 그 칸에 떨어뜨림. 옆 벽(더 높은 칸)에 부딪히면 그 앞 칸, 경기장 밖으로 넘어가면 마지막으로 지난 안쪽 칸. 서서 평평한 곳이면 약 3~11m, 점프하며 던지면 더 멀리. 날아가는 모습은 던진 방향 직선 위의 닿는 점(`end`)까지 똑바로 가고, 닿은 뒤 칸 가운데로 살짝 미끄러짐. **날아가는 폭탄이 사람 몸(발~머리 세로 막대, 1.1m 안, 틱 사이 구간도 검사)에 맞으면 그 사람이 살짝 밀리고 폭탄은 그 사람 발밑 칸으로 툭 떨어진다** (`_redirect_bomb`, 알림 `redir`). 부서지지 않는 블록 위로 던져도 그 위에 떨어져 터진다(그 높이에서 터지므로 아래 칸까지는 1층만). 탭 = 발밑 칸(가장자리 밖으로 떨어지는 중이어도 가장 가까운 안쪽 칸). 차징 중엔 떨어질 칸(노란 고리)과 터질 범위(노란 칸 타일)가 보인다 (`Fighter.throw_mode` → `on_throw(f, -1 또는 0~1)`). 밀치기는 없음 **던지거나 놓은 뒤 쿨타임(기본 0.8초, `throw_cooldown`) 동안은 움직이지도 점프하지도 못한다.** **쿨타임 중에 누른 것은 탭·차징 모두 무시** — 쿨타임이 끝난 뒤 새로 눌러야 한다. 화면 아래 던지기 막대(돌피하기와 같은 모양)가 쿨타임 동안 파랗게 차오르고 위에 "쿨타임 0.5초"가 보인다 (차징 = 노랑→빨강, 준비 = 청록). 던질 폭탄이 없으면 "폭탄이 터져야 다시 던져요"
- 카메라: 돌피하기와 같은 3인칭(거리 5.5m, 캐릭터가 1.3배라 조금 더 멀리). 마우스·터치 드래그로 돌리고, 마우스 휠로 2.5~24m 당기거나 밀기. 유령이 되면 12m 이상으로 물러나 유령을 따라감

## 규칙 (`games/bomber/bomber_game.gd`, 격자 `board.gd`)
- 경기장은 정사각형, 인원에 따라: 3명 이하 13×13 / 5명 15×15 / 8명 17×17 / 9~12명 19×19 (칸 = 블록 한 변 2m). 처음엔 모든 칸이 블록 4층(`LAYERS`)으로 평평하다. 블록마다 모서리에 진한 테두리 선(`shaders/block.gdshader`)과 체크무늬 색으로 한 칸씩 구분된다. 출발 칸은 안쪽 테두리 줄에 고르게
- 부서지지 않는 블록(회색 돌): 테두리와, (짝수, 짝수) 칸 중 엇갈려 절반. 다른 블록과 높이가 같아 위에 설 수 있고, 폭발에 안 깎인다(그 위에 선 사람은 범위 안이면 맞음). 경기장 가장자리에 벽이 없어서 밖으로 떨어져도 탈락
- 폭탄: 던진 자리에서 포물선으로 날아가(0.18초 + 거리 비례) 떨어진 칸 꼭대기에 놓이고, 1.6초 뒤(`LAND_FUSE`) 터짐. 날아가는 폭탄에 맞은 사람은 날아가던 쪽으로 살짝 밀려남(`BOMB_HIT_PUSH`, 던진 사람 자신은 제외). **범위는 정사각형**: 기본 3×3칸(폭탄 칸 가운데), 불꽃 아이템을 먹으면 4×4 — 짝수라 던진 방향(x·z 각각) 쪽으로 한 칸 더 (`Board.blast_box`, 폭탄마다 `skew`). 높이는 폭탄 층 위아래 1층 — 한 층 아래 칸에 있어도 범위 안이면 맞는다. 범위 안의 다른 폭탄도 바로 터짐(연쇄). 구멍에 떨어진 폭탄은 용암에 빠져 사라짐 **곧 깎일 블록은 여섯 면 모두 빨간 상자로 덮어 보이고(칸마다 깎일 층만, `_place_zone`), 터질 범위는 칸마다 빨간 타일(굵은 흰 테두리 + 움직이는 빗금)로 각 칸 꼭대기에 붙어 보인다** — 날아가는 동안은 옅게, 떨어진 뒤엔 진하게, 터질 때가 가까울수록 빨리 깜빡인다(`ZONE_SHADER`).
- 블록 깎기: 범위 안 부서지는 블록이 위아래 1층 안까지 쌓여 있으면 그 블록들이 사라져 높이가 (폭발 층 − 1)이 된다 (평평한 곳이면 1층 깎임, `Board.height_after`). 훨씬 높은 탑·낮은 칸은 그대로. 높이 0 = 구멍
- **탈락**: 불길에 맞음 (범위 칸 안 + 발 높이가 폭발 층 꼭대기 기준 아래 2.3m ~ 위 1.5m 안(`HIT_BELOW`·`HIT_ABOVE`) — 점프해서 더 높이 떠 있으면 안 맞음, `FLAME_TIME` 0.4초 동안) 또는 가시 바닥(구멍 아래)·경기장 밖으로 떨어짐. **내 폭탄·아군 폭탄 불길에도 맞는다** — 내 폭탄이 날아가는 동안 나를 밀지는 않음. 마지막 1명(팀전은 1팀)이 남으면 승리. 경기장은 좁아지지 않고, 제한 시간 150초가 끝나면 남은 사람끼리 공동 1등
- 아이템: 블록이 깎인 칸에서 14% 확률로 나옴 — 쿨타임(던진 뒤 쿨타임 -0.15초, 최대 3개, 가장 잘 나옴 42%) / 폭탄(동시에 던질 수 있는 개수 +1, 최대 6, 24%) / 속도(+0.9m/s, 최대 3개, 20%) / 불꽃(범위 3×3 → 4×4, **한 번만**, 14%). 모양으로 구분: 쿨타임 = 초록 시계, 폭탄 = 보라 폭탄(진짜 폭탄은 검정), 속도 = 하늘색 ▶▶ 화살표, 불꽃 = 주황 불꽃 — 바닥에 같은 색 빛 고리, 위에 "쿨타임 -"·"폭탄 +1"·"속도 +"·"범위 +" 글자. 시작은 폭탄 1·범위 3×3·속도 7.2m/s·쿨타임 0.8초
- 사람끼리는 서로 통과 (좁은 길에서 마주쳐 막히지 않게)
- **유령**: 탈락 1초 뒤 경기장 바깥 테두리 위에 뜬 유령이 된다. 이동 키로 테두리를 돌고, 던지기 키(또는 점프 키)로 안쪽에 폭탄을 던진다(반경 1, 한 번에 1개 — 던진 폭탄이 터지면 바로 다시 던질 수 있음, 떨어질 칸은 서 있는 변에서 안쪽으로 3·2·4·1·5번째 서 있을 수 있는 칸 순). 유령은 맞지 않고, 유령 폭탄도 누구든 맞힌다
- 순위: 살아남은 사람 → 늦게 탈락한 순. 팀전은 살아남은 팀원 수 → 마지막 팀원이 탈락한 시각
- 온라인: 클라이언트는 `["throw", 떨어질 칸, 던진 위치, 던진 높이, 치우침]`·`["gthrow", 유령 위치]`·`["gh", 유령 위치]` 를 보내고, 서버가 `bomb`(칸·던진 위치·떨어지는 시각·터지는 시각·던진 높이·치우침)·`sink`·`boom`(터진 폭탄들, 불길 묶음[칸·주인·높이·반경], 깎인 칸·층 수, 탄 아이템, 새 아이템)·`item`·`out`·`ghs`(유령 위치 10Hz) 를 알린다. 탈락 판정은 "그 시각의 내 위치"로 (내 화면에서 피했으면 피한 것)
- 봇 (`bot_brain.gd`): 0.2~0.4초마다 생각. 지금 칸이 곧 터질 자리면 안전한 칸으로 도망(구멍은 피하고 2층까지는 점프로 오름, 지나가는 칸의 불길 시각까지 따짐), 상대가 4.5~11m 안이면 몸을 돌려 거리만큼 차징했다 던짐(실력이 낮으면 조금 빗나감), 상대가 내 폭발 범위 안이고 도망칠 길이 있으면 발밑에 놓고 도망(내가 맞을 자리면 안 던짐), 쿨타임 중엔 누르지 않고 끝난 뒤 새로 누름, 가까운 아이템 줍기, 상대에게서 2~4칸(던질 수 있는 거리) 떨어진 자리로 이동. 봇 유령은 가장 가까운 상대 쪽 테두리로 가서 던짐
- 화면 (`hud.gd`): 위 = 남은 시간·생존(팀전은 팀별), 아래 = 내 폭탄 수·범위·속도·쿨타임과 던지기 막대(쿨타임·차징·준비), 탈락하면 유령 안내와 다시 던질 때까지 남은 시간, 오른쪽 아래 = 작은 지도(높이를 색으로, 구멍은 주황, 폭탄·불길·사람)
- 효과음: `tools/audio/gen_bomber.py` → `audio/sfx/{bomb_place,boom,kick,crate_break,ghost_throw}.wav` (던질 때 bomb_place, 떨어질 때 kick)
- 경기장 바닥은 **가시 구덩이**: 어두운 바닥에 쇠 가시(0.8m 간격, 높이 1.6m, `_build_spikes`)가 촘촘해서 구멍이 뚫리면 떨어지면 죽는다는 게 보이고, 경기장 바깥 둘레 3m 에도 가시 띠. 바닥 판은 땅보다 0.45m 솟아 있음(`FLOOR_LIFT`) — 짧게 깎인 풀이 뚫고 보이지 않게. 블록 충돌은 8번 층(카메라 팔에 걸리지 않게). `module.gd` 의 `arena_half = 26`
- 개발용: 환경변수 `SPW_BOTS=11` 이면 혼자 연습 봇 수를 바꿈

## 새 게임 추가 방법
1. `games/<id>/` 폴더를 만든다.
2. 게임 스크립트 작성: `extends PartyGame`. `_ready()`에서 아레나·캐릭터를 만들고
   `state` 를 `State.COUNTDOWN → PLAYING → ENDED` 로 진행한다. HUD를 만들 때 `add_common_ui(layer)`를 부르면 터치 UI가 붙는다.
   `online_match`(Net.match_config)에 방 정보·참가자·봇 수가 들어 있다.
   온라인 대응: 같은 스크립트가 서버(`is_server()`)와 클라이언트(`is_client()`)에서 돈다.
   서버는 `on_client_message(pid, msg)`, 클라이언트는 `Net.game_message` 로 메시지를 받는다 (움직이는 게임은 돌피하기, 박자·결과만 주고받는 게임은 뒷북의 달인 모듈 참고).
3. `games/<id>/module.gd` 작성 (`extends "res://scripts/core/game_module.gd"`, `_init()`에서 id·이름·설명·인원·`game_script_path` 지정).
   **게임 스크립트를 preload 하지 말 것** — 레지스트리는 오토로드(Net)보다 먼저 컴파일되므로 경로 문자열만 둔다.
4. `scripts/core/game_registry.gd` 의 `MODULES` 에 `preload("res://games/<id>/module.gd")` 한 줄 추가.

이것만으로 접속 화면(오프라인 연습 목록), 방 만들기, 대기룸 게임 선택, 서버 검증·상태 페이지에 새 게임이 나타난다.
